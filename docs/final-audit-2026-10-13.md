## 本次发现与修复清单

| 编号 | 问题 | 修复与边界 |
|---|---|---|
| 01 | 相同行程 ID 的用户导出可能互相覆盖 | 每次导出使用独立随机目录；源文件也放入受清理管理的界面缓存 |
| 02 | ICS 没有时区、生成时间，跨设备可能错时 | 使用 UTC 的 DTSTART/DTEND，增加 DTSTAMP 和独立 UID |
| 03 | 上传与导出临时文件缺少定期清理 | 启用 Gradio 每小时清理超过一小时的缓存；原图不进入浏览器历史，过期需重新上传/导出 |
| 04 | 解析失败退回服务端次数，反复重试可能绕过费用保护 | 上传先做本地文件检查；发出云端请求后的失败保留服务端计数，并说明原因 |
| 05 | Managed Agent 发消息的超时重试可能重复提交计费任务 | 非幂等请求不自动重试；GET 查询仍有有限重试 |
| 06 | 界面超时后云端任务可能继续运行 | 公网路径在异常时尝试中断当前会话；不能保证平台即时停止，不退回已发生费用 |
| 07 | “实时巡检”有时只做本地检查 | 自行上传行程的首次显式巡检真正调用高德；需要新候选的已知风险会在同一轮查询 FlyAI，避免先巡检再生成方案重复消耗次数；示例明确标为演示/本地检查 |
| 08 | 单段车票不能核验天气，或同站衔接被要求查询跨城公交 | 单段/同站不强求公交路线，仅查询对应城市天气；天气未覆盖的日期保持未核验 |
| 09 | 已获取工具结果可能无限复用 | 实时核验和候选缓存有效期一小时；再次执行受每日次数限制，历史结果仍按获取时间查看 |
| 10 | 修改/重建行程后旧 Plan B、聊天、导出或候选仍可能残留 | 失效相关结果；移除旧路线/天气证据、候选及时间戳，重新确认后再检查 |
| 11 | 删除单张图片未失效已构建行程 | 删除与清空均重置旧结果并保存会话状态 |
| 12 | 重新解析可能沿用之前的低置信确认勾选 | 每次重新解析重置确认状态 |
| 13 | 置信度越界或模型遗漏低分提示 | 分数限制为有限的 0–1；后端自动补上低于 0.8 的字段 |
| 14 | 人工确认后提示仍像未确认，或误称全部字段没有低分 | 保留原始置信度，标注已人工确认，不把 0.5 改为 1 |
| 15 | 缺失/无效日期显示技术性异常，跨日结束难修复 | 按第几项显示日期/时区/时间顺序提示；表格补全具体时间字段 |
| 16 | 关联编号异常的草稿难以纠正 | 提供相关前置/保护编号补全项；已解析草稿可展开高级 JSON 校对，但仍不视为构建完成 |
| 17 | 空 travelers/constraints、空 metadata 可能导致崩溃 | 规范化为空对象或待补全字段，失效订单检查容错 |
| 18 | 缺内部 ID、版本或总体日期会让普通用户填写技术字段 | 内部编号自动生成；总体日期从实际事件推导，不借用广告日期 |
| 19 | 全是老人出行仍被强制要求一个额外成人 | 成人可为零，成人/儿童/老人总数至少一人；不替代实际出行规则判断 |
| 20 | 无前置关联的两张车票可能漏查换乘 | 同站短缓冲补检；不同站点没有耗时证据时明确列为未核验，不默认零耗时 |
| 21 | 夜间车次跨日可能误报缺住宿 | 跨午夜交通覆盖该夜时，不直接要求另订酒店；只检查已导入行程范围 |
| 22 | 风险卡片遗漏数据质量、天气及预算未核验警告 | 展示待核验信息、中文预算/严重程度，并明确“零风险不等于整趟旅行已核验” |
| 23 | 交通冲突建议让用户只改截图时间 | 改为选择保留有效交通或查询其他实际车次；不实际退改 |
| 24 | 视觉模型可能附带虚构 MCP 证据或任意身份字段 | 模型输出按结构字段过滤，metadata 只保留订单事实；风险由规则计算。不是对原图或所有自然语言的完整自动匿名化 |
| 25 | 一个城市的天气可能被应用到另一个城市；路线只匹配终点 | 天气同时匹配城市与日期；路线同时匹配前段终点和后段起点，未知精度/错误 MCP 输出不当作有效定位 |
| 26 | 候选来源只验证“有命令执行成功”，未绑定具体商品 | 候选名称、链接和单一价格需对应本次成功 CLI 业务 JSON；拒绝模型编出的链接/金额；未知价格或区间价格不能确认预算 |
| 27 | EXIT:0 被当作 FlyAI 业务成功，工具轨迹不论失败都声称全成功 | 必须有实际业务 JSON 状态；显示真实成功数量 |
| 28 | 重规划提示缺原始完整行程，或遗漏无已有酒店的补住宿风险 | 提供完整 TripGraph 和相应新增修复任务；提示最多 3 次 FlyAI 查询、8 次高德调用。此提示约束不能代替平台账单硬保护 |
| 29 | 新总价与增量重复计入候选回放预算；NaN 金额异常 | 新价格不重复叠加增量，另外检查原计划费用加增量上限；拒绝非有限金额，未假设退款已到账 |
| 30 | 问答缺实际车次/事件，服务故障回复被长期缓存 | 问答包含当前事件与未核验警告；故障回复不缓存；问题最多 500 字，不改变 100 字回复限制 |
| 31 | 仅选择示例但未构建也可问答；预定/预订免费规则不一致 | 未构建先给本地提示；单行程示例的标准“预订/预定”两种写法均免费，用户行程仍按原规则计数 |
| 32 | 异常大行程及不存在的保护编号缺少限制 | 单次最多 100 事件、366 天；保护编号必须属于当前行程 |
| 33 | 部分能力说明与实际行为不符；本地密钥只读系统变量 | 修正 Plan B/巡检范围说明，说明原图不自动打码；浏览器密钥和限流盐也支持本地 .env 固定配置 |
| 34 | 巡检后工具轨迹可能仍显示之前的本地记录 | 显式巡检完成后刷新当前会话工具轨迹，不能声称未调用工具 |
| 35 | 总预算超限时没有指出可查询替代项的费用节点 | 预算风险关联当前有已知费用的节点，交给保护约束和工具检索处理；不能通过新增费用虚假解决超支 |
| 36 | 手机比较表显示冗长内部编号、ISO 时间与换行金额 | 调整节点使用中文行程名称，日期用月日时分，金额与风险数字不拆行；保持已确认的主题与纵向步骤布局 |

## 验证结果

- `python -m pytest -q`：125 项通过，新增独立最终审查回归用例；所有付费接口在新用例中均为模拟调用。
- Ruff：通过。
- `python scripts/evaluate_offline.py`：2 个案例通过，历史杭州黄金案例结论保持不变。
- `git diff --check`：通过；Windows LF/CRLF 提示不是校验失败。
- 凭据扫描：从本地配置中读取 5 个实际配置值，只报告统计；当前 92 个受检仓库文件/新增测试精确匹配为 0。不是所有历史提交与所有日志的完整安全审计。
- 本地浏览器：正常两段车票构建、风险检查、无需 Plan B；冲突三段车票生成两个调整方案并应用，风险 1 → 0；切换图片清理旧结果；高级编辑区固定高度。
- 390×844 响应式检查：文档宽度没有超过视口，步骤纵向排列，图片预览固定高度并可滚动。不是对所有真实手机浏览器的兼容性保证。
- 代码中的会话中断按 [百炼官方事件协议](https://help.aliyun.com/zh/model-studio/managed-agents-event-stream)实现；此次仅模拟验证，没有对用户已存在的云端会话发送中断。

## 未执行或尚有边界的事项

1. 未进行新的付费视觉、文本、Managed Agent 或 FlyAI 真实调用。新候选绑定与云端中断尚需部署后实际验证；不同上游返回格式可能导致保守拒绝，而不是假造结果。
2. 公网仍需用户重新部署后，完成真实截图、手机网络、无痕窗口和额度限制验收。不能将本地测试描述为公网已验收。
3. 匿名 IP/浏览器特征限流不等于实名用户隔离：共享网络可能合并部分访客、换设备/网络可能改变标识；全站计数仍作为最后一层保护。容器重建/多实例不能用单机临时 SQLite 充当跨实例永久总账。
4. 一次 Agent 调用可能产生多次模型/工具费用；按调用次数保护不是人民币硬预算。必须继续在百炼控制台保留额度/余额保护并检查账单，不能仅靠网页次数限制保证零额外费用。
5. 当前没有用户级自动定时监控、通知、账户登录或跨设备历史。杭州 Scheduled Task 记录是历史示例；页面上的核验由用户显式触发。需要这些能力时是新的产品范围。
6. 原图只做文件格式/大小检查及元数据归一化，不自动遮挡画面。结构过滤降低个人字段保留风险，但自然语言标题/备注仍可能残留用户写入的信息；仍应自行脱敏。
7. 局部移除冲突项不适合“两个目的地都必须去”的情况；其他情况依赖真实供给与证据，有可能无法生成有效 Plan B。单段车票不代表完整旅行，未导入的住宿/景点不应被当作已核验。
8. 模型配置/经济档、账户余额、Agent 权限与 Skill 挂载必须在平台验收；本次未自行更换模型或放宽授权。
9. 保留用户未跟踪的 `assets/长白山到沈阳北.png`，未提交或公开。
