# 巡检保留待选 Plan B 与操作计时修复

日期：2026-10-14。此前应用基线为 `596bcc7`，最近文档交付为 `a47d7b1`。

## 原因

- 新的实时核验结束后，无条件移除了 `local_plan_options`，导致用户尚未应用的局部 Plan B 消失。
- 自动保存重绘下拉框时总是选择第一项，没有保留用户当前选择。
- 上轮加载修复将进度改为结果区域的 minimal 模式，虽然避免整块遮罩，但即时反馈不够明显，尤其是短操作和折叠区中的操作。

## 修复

1. 巡检不替用户选择目的地。已有待选方案时，基于新证据重新回放校验并刷新费用 / 风险；仍有效的方案保留。全部失效则明确说明原因、要求重新生成，不悄悄清空或沿用过时方案。
2. 下拉框当前选择进入会话快照，在自动保存、风险复检、巡检和历史恢复后保持有效选择。重新导入时清除旧选择；应用方案后才收起待选区。
3. 用独立服务端 State 保存选择，避免其他操作的自动保存读取已经清空的下拉框。应用后延迟到达的旧选项事件会被忽略，不再弹出“选项不在 choices 中”。实际应用仍按当前 TripGraph 重新计算和校验，不信任前端传来的候选。
4. 解析、构建确认、编辑校验、风险检查 / 复检、Plan B、方案应用、巡检、问答与导出，在各自按钮旁使用紧凑加载状态条。原生转圈和递增秒数只覆盖此小区域；已有行程、置信度和工具证据继续可读。完成后显示实际服务端执行耗时（不含排队 / 往返）；不会为了让用户看见计时而人为延迟。
5. 服务端操作失败显示“未完成”，成功分支不会继续执行；切换历史时重置操作状态条，避免显示另一会话的旧耗时。网络在入队前中断时由框架结束加载，已有结果保留，可显式重试。

## 验证

- 自动化：171 项通过；离线评测 2 个案例通过；Ruff、编译与 diff 检查通过。
- 新回归覆盖：真实上传来源的巡检分支使用模拟结果重新校验候选；费用随更新后的 TripGraph 刷新；巡检失败不修改待选方案；选择在快照中恢复；延迟选择事件安全忽略；计时包装器保留 Request 注入和限流逻辑。
- 本地 Edge 桌面与 390px 手机宽度：生成 Plan B → 改选第二项 → 先巡检不应用 → 再检查风险，方案区与选择均保留；应用后正常收起。延迟请求期间计时秒数递增，其他面板可读；连接失败后重试和刷新历史均通过。
- 浏览器脚本：[check_loading_ui.cjs](../scripts/check_loading_ui.cjs)。浏览器只使用公开车票示例；真实巡检分支通过模拟 HTTP / 返回值测试，没有新增真实百炼、高德 MCP 或 FlyAI 付费调用，不将这些测试当作最新公网云端工具验收。

## 部署后重点复测
